Token Consensus Decoding

Simultaneous EN→ZH translation via token-level agreement across imagined futures.

The problem
Simultaneous translation must write before it has finished reading.
Once a target word is emitted to the user, it is irreversible. Commit too early and later source may reveal the prefix was wrong — but you can no longer fix it.
Source (streaming)
The bank was … flooded
Translator
银行 → oh, it was the river bank!
Early commitment = permanent mistake. This project makes the commit decision future-aware.

Why this matters.

Simultaneous translation is the technology behind real-time subtitles, live interpretation, cross-lingual video conferencing, and emergency communication. Even small improvements compound over billions of words.

USE 1

Live subtitles

Conferences, lectures, news broadcasts. A viewer cannot "replay" a wrong caption.

USE 2

Interpretation assist

Human interpreters lag 2–4 seconds — software can pre-fill drafts if it's trusted.

USE 3

Accessibility

Deaf / Hard-of-Hearing users rely on accurate real-time translation to participate.

Measurable objective: improve BLEU by ≥5 over wait-k baseline on WMT19 EN→ZH at equal latency.

Prior work: three threads.

THREAD 1

Wait-k policies

Fixed read/write schedule: wait for k source words, then alternate (Ma et al., STACL 2019). Pure latency control, no uncertainty awareness.

THREAD 2

Test-time compute

Self-consistency (Wang et al. 2023), Self-Refine (Madaan et al. 2023), CALM (Schuster et al. 2022) — spend more at inference for better answers.

THREAD 3

MT uncertainty

Fomicheva et al. 2020; Cheng & Vlachos 2024. Measure model confidence, but do not use it for streaming commit.

Gap: no prior work uses future-sampled consensus to decide what streaming prefix is safe to commit. That's what this project does.

Evaluation metrics (with formulas).

BLEU (quality)

BLEU = BP · exp( ∑n=1..4 wn log pn )

n-gram precision vs. reference, with brevity penalty BP. Character-tokenised for Chinese via sacrebleu.

COMET (semantic)

COMET(src, mt, ref) = regressor(XLM-R encodings)

Neural score trained on human DA judgments (Rei et al. 2020). Correlates ~0.75 with humans; tolerates paraphrase.

AL (latency)

AL = (1/τ) · ∑t=1..τ ( d(t) − (t−1)/γ )

Average source words read before emitting target word t (Ma et al. 2019). Lower = more responsive.

We report all three on the same 1997 sentences — quality and latency trade-off is what matters for streaming.
The big idea
Don't commit based on one plausible translation.
Commit based on what many imagined futures agree on.
visible prefix
"The bank was"
future 1: "The bank was robbed by three gunmen"
future 2: "The bank was flooded after the storm"
future 3: "The bank was approved for the loan"
future 4: "The bank was founded in 1872"
all futures start with
"The bank"
→ safe to translate

Method 1: DD + JS gate — when to wait.

Measure disagreement between future-conditioned next-token distributions using Jensen–Shannon divergence. High JS → futures disagree → wait.

JS(P ‖ Q) = ½ · KL(P ‖ M) + ½ · KL(Q ‖ M),   M = ½(P + Q)
Read if   meank JS(Pk ‖ Pk') > τ
Result: +1.00 BLEU, but +0.78 AL — DD buys quality by reading more source.

Method 3: Token Consensus — go one level deeper.

Forget strings. Look at the translator's next-token probability distribution under each future. Intersect the top candidates.

STEP 1

Sample futures

K=10 English continuations from Qwen3-4B-Base

"was robbed"
"was flooded"
"was approved"
"was founded"
STEP 2

Query translator

For each future: Qwen30B next-token distribution, force committed prefix

P₁, P₂, …, P_K
(each: top-20 Chinese tokens with probs)
STEP 3

Intersect

Hard intersection of top-k token IDs across all K distributions

I = ∩ pool(P_k)
|I| > 0
STEP 4

Commit

Token with highest average probability across futures

米
Key insight: consensus over token IDs, not strings. Tolerates lexical freedom because next-token distributions depend on committed prefix, not full translation.

Honest limitations.

⚙️

Compute cost

K extra API calls per commit step. ~1.5× wall-clock vs direct wait-k.

🧊

Hard intersection

One noisy future can empty the intersection and force a read. Soft quorum untested.

🔌

Needs top-k logprobs

Black-box APIs that only stream text cannot be used as the translator.

🌏

Only EN→ZH tested

Chinese's lexical freedom is exactly what TC fixes. Other pairs may benefit less.

🎲

Stochastic futures

Temperature sampling → 2 runs vary by ±0.2 BLEU. Fix the seed for reproducibility.

🎙️

Offline ASR pilot

CoVoST speech pilot uses offline Whisper (not streaming). End-to-end is future work.

Why does it work? What did we learn?

INSIGHT 1

Consensus > gating

Building a safe prefix (+3.8–6.0 BLEU) beats deferring with a gate (+1.0 BLEU). Deciding what to write beats deciding when to wait.

INSIGHT 2

Tokens > characters

Surface-level LCP collapses under lexical variation. Token-level distribution consensus is robust because it depends on the committed prefix, not full translations.

INSIGHT 3

Pool shape matters

Top-p=.95 (nucleus) beats all fixed top-k (+1.8 BLEU). The pool should adapt to distribution peakedness: tight pool when confident, loose when uncertain.

Where it goes from here.

NEXT · 1

Soft quorum

Replace hard "all K agree" with "≥80% agree" to trade off precision/recall.

NEXT · 2

Adaptive K

Fewer futures on easy prefixes, more on ambiguous ones — halves compute.

NEXT · 3

Streaming ASR

Replace offline Whisper with streaming Whisper-Large-v3 for true end-to-end speech.

NEXT · 4

Other languages

Test on EN→DE / EN→JA to confirm benefit isn't only from Chinese lexical freedom.

Simultaneous MT is a safe-commitment problem, not a fixed-delay one.

  • Token Consensus Decoding: intersect token-level distributions across imagined futures.
  • Training-free: drops onto any translator that exposes top-k log-probs.
  • Robust to Chinese lexical freedom — where character-level LCP collapses.
  • +6.97 BLEU / +0.078 COMET on WMT19 EN→ZH (1997 sentences). Nucleus (top-p) pool beats fixed top-k.
